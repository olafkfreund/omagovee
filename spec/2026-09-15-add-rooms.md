# Spec: Add new rooms and move lights between them reliably

## Design

Room data stays as it is: `~/.config/omagovee/rooms.json`, `{room: [device
name, ...]}`, a device in at most one room, no empty rooms. Every rule lives
in `bin/omarchy-govee`; the panel only gains a way to ask for a new room and
a way to show why a command was refused.

### CLI — `bin/omarchy-govee`

1. **Repair on load.** `load_rooms()` drops any device already seen in an
   earlier room (file order, which `json.load` preserves), removes repeats
   inside one room, and drops rooms left empty. The repair is in memory
   only; it reaches disk on the next room write. Reads (`dump`, which runs
   every minute) never write files. Every caller — `assign_room`, `rename`,
   `resolve_many`, `dump` — sees repaired data because they all go through
   `load_rooms()`.

2. **Room name check.** A new `check_room_name(name)` dies with a message
   when the name is empty after stripping, or is one of `none`, `other`,
   `all`:
   - `none` means "no room" to `assign`;
   - `other` is the panel's heading for unassigned devices, and a drop on it
     unassigns (`plugin/Govee.qml:296`);
   - `all` is a target keyword that sits next to `room:<name>` in the usage.
   Called for the target of `rooms assign` (except the literal `none`) and
   the new name in `rooms rename`. Names are stored stripped.

3. **`rooms <room> <device>...` aliases `rooms assign`.** The branch at
   `:642` is replaced by the assign path, so the devices are resolved to
   their Govee names and moved out of any other room. It no longer replaces
   the room's member list. `rooms none <dev>` therefore unassigns, as
   `assign none` does.

4. **`assign_room` ignores repeated names** in one call
   (`list(dict.fromkeys(names))`) so `rooms assign a x x` cannot store `x`
   twice.

5. **`rooms rename <old> <new>`** is refused when `<new>` already exists
   ("room 'hall' already exists — move its lights with `rooms assign`"),
   and runs `check_room_name`. Scenes referencing `room:<old>` are still not
   rewritten (already documented).

6. **Device lookup picks an exact match first.** `resolve(name)`:
   1. exact, case-insensitive match on Govee name, MAC or label → that
      device;
   2. otherwise substring matches as today; exactly one → that device;
   3. more than one substring match → die, listing the candidates, instead
      of taking the first.

   This applies to every command that takes a device, not only rooms,
   because they share `resolve`. `default.json` stores exact names, so the
   default device is unaffected.

### Panel — `plugin/Govee.qml`

7. **New room field.** In a device's expanded controls, directly under the
   room chips (`:621`), a `TextField` with placeholder "New room…". On
   Enter: trim; if non-empty, `act(["rooms", "assign", text, dev.name])`;
   clear and unfocus. It uses the same `editors` counter as the other
   fields so the key catcher stands down while typing. The room appears
   after the refresh that follows every action, as a heading and as a
   chip, and other lights can then be dragged into it.

8. **Drop anywhere on a room.** The room delegate becomes an `Item`
   (`id: roomItem`, width `column.width`, `implicitHeight` from an inner
   `Column`) holding the existing Column plus the `DropArea` and its
   highlight `Rectangle`, both `anchors.fill` the whole room. They cannot
   stay inside the Column: a Column refuses anchored children. The
   `onDropped` logic is unchanged. The drag source, the handle
   `MouseArea` with `preventStealing`, and the `z` raise are left as they
   are. The heading keeps growing during a drag.

9. **Say why a command failed.** `actionProc` gets a
   `stderr: StdioCollector`. `onExited: function (code)` reads the stderr
   text first, then — if `code !== 0` —
   `Quickshell.execDetached(["notify-send", "-a", "Omarchy", "Govee failed",
   text])`, then does the existing `busyName` / `pump()` / `refresh()`.
   Reading before `pump()` matters: `pump()` starts the next queued command
   on the same Process. This matches the pattern in `bin/omarchy-cmd-lights`
   (critical notify on failure) and the `onExited: function (code)` +
   collector `.text` pattern used by other Omarchy plugins. It covers every
   panel action, not only rooms — a toggle on an offline light now says so
   instead of silently snapping back.

### Tests — `test_omagovee.py`

Stub `govee.devices` with a fixed list and point `CONFIG` at a temp dir, as
the existing room test does, then drive `govee.main([...])`:

- `rooms <room> <dev>` moves: device ends in exactly one room.
- `load_rooms()` repairs `{"a": ["x", "y"], "b": ["x"]}` to `{"a": ["x",
  "y"]}`.
- `rooms rename a b` with `b` existing → `SystemExit`, file unchanged.
- `rooms assign other x` and `rooms rename a none` → `SystemExit`.
- `resolve`: with devices `lvrt1` and `lvrt10`, `lvrt1` → `lvrt1`;
  `lvrt` → `SystemExit` (ambiguous).

### Docs — `README.md`

Rooms section: new-room field, reserved names, rename refusal, the
`rooms <room> <dev>` form now moving lights, ambiguous names being refused,
failure notifications from the panel.

## Alternatives rejected

- **Empty rooms (create first, fill later).** Needs persistence of empty
  rooms, drawing them, and a rewrite of the existing "empty room disappears"
  test. Rejected by the approver in favour of creating a room with its first
  light.
- **Merge on rename onto an existing room.** Easy to trigger by typo, awkward
  to undo. Rejected by the approver.
- **Writing the repaired `rooms.json` during load.** `dump` runs every
  minute from the bar; a read that writes files is surprising and races with
  panel actions. Repairing in memory gives the same view with no write.
- **Checking reserved names in QML before calling the CLI.** Duplicates a
  rule the CLI must enforce anyway and breaks the "panel holds no logic"
  constraint; the notification in (9) gives the same feedback.
- **A "drop here to create a room" zone shown during a drag.** Still needs a
  way to type a name mid-gesture; more QML for the same outcome as (7).
- **Keying rooms by MAC instead of name.** Would make labels and renames
  irrelevant to rooms, but needs a migration of every `rooms.json` and
  `scenes.json`. Out of scope.
- **Keeping first-substring-match in `resolve`.** It is how `lvrt1` moves
  `lvrt10`; exact-first alone still leaves `lvrt` picking arbitrarily.

## Risks

- **Ambiguous names now fail everywhere.** A scene target, a keybinding or a
  habit like `omarchy-govee toggle desk` that matched two devices used to
  pick one silently and will now exit non-zero with the candidate list.
  Correct, but visible. Desktop only; the fix is to use the full name.
- **Room delegate restructure could regress the drag** fixed in 2128726.
  Only the container changes, not the handle or `Drag` properties, but the
  gesture cannot be tested from a shell. Checked at runtime via the journal
  lines `govee drag start` / `govee drop`.
- **Notification on every failed action** may be noisier than before when
  lights are offline. That is the intent of (9); if it proves too noisy,
  limit it to room commands.
- **Repair picks "first room in the file"** for a device that is in two
  rooms; if the user wanted the second, they move it once. No data is lost
  beyond the duplicate entry.
- **Renaming `rooms <room> <dev>` semantics** from replace to move: a script
  relying on it to *remove* other members from that room would stop doing
  so. None known in this repo (checked README and `omarchy-cmd-lights`).

## Verification

- `python3 test_omagovee.py` → all tests pass, including the new ones.
- CLI against a scratch config (`OMAGOVEE_CONFIG` in the scratchpad), no
  API needed: `rooms office lvrt1` with `lvrt1` already in `hall` leaves it
  only in `office`; `rooms rename office hall` refuses; `rooms assign other
  x` refuses.
- Panel, on the desktop (`cp -r plugin ~/.config/omarchy/plugins/olafkfreund.govee
  && omarchy restart shell`):
  - expand a light, type a new room name, Enter → new heading and chip
    appear, light is under it;
  - drag another light and drop it on that room's *device list*, not the
    heading → it moves; `journalctl --user -f | grep govee` shows
    `govee drag start` and `govee drop`;
  - type `other` in the new-room field → "Govee failed" notification naming
    the reserved name, nothing moves;
  - scrolling the panel still works when not dragging.
